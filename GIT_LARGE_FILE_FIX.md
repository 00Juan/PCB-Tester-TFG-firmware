# Git Large File Problem — Root Cause & Resolution

**Date:** 2026-07-18  
**Repository:** `PCB-Tester-TFG-firmware`  
**Branch affected:** `main` (and all other branches via shared history)

---

## Problem

When trying to push local commits to GitHub, the push was rejected with the following error:

```
remote: error: File pc/.venv/lib/python3.9/site-packages/PySide6/Qt/lib/QtWebEngineCore.framework/Versions/A/QtWebEngineCore is 446.12 MB; this exceeds GitHub's file size limit of 100.00 MB
remote: error: GH001: Large files detected. You may want to try Git Large File Storage - https://git-lfs.github.com.
To https://github.com/00Juan/PCB-Tester-TFG-firmware.git
 ! [remote rejected] main -> main (pre-receive hook declined)
error: failed to push some refs to 'https://github.com/00Juan/PCB-Tester-TFG-firmware.git'
```

### Root Cause

The Python virtual environment directory `pc/.venv` was **accidentally committed** to the repository. This directory is auto-generated by Python and contains all installed packages for the project, including PySide6.

One of PySide6's bundled libraries — `QtWebEngineCore` — is a **446 MB binary file**, which far exceeds GitHub's maximum allowed file size of **100 MB**.

Since the file was embedded in the git history (not just the working tree), simply deleting it and committing again would not have been enough — the large object would still exist in past commits and would be sent during a push.

The `.git` directory had grown to approximately **373 MB** because of this.

---

## Resolution

### Step 0 — Local Backup

Before modifying any history, a full backup of the repository was created:

```bash
cp -r PCB-Tester-TFG-firmware PCB-Tester-TFG-firmware_backup_20260718_230745
```

### Step 1 — Install `git-filter-repo`

`git-filter-repo` is the modern, recommended tool for rewriting git history. It was already available in the system:

```bash
pip install git-filter-repo
# → Already installed: version 2.47.0
```

### Step 2 — Purge `pc/.venv` from Entire History

The following command rewrote all 33 commits across all branches, removing every trace of `pc/.venv`:

```bash
git filter-repo --path pc/.venv --invert-paths --force
```

> **Note:** `git filter-repo` automatically removes the `origin` remote as a safety measure to prevent accidental pushes before verification.

**Result:**
- `.git` directory size: ~373 MB → **592 KB**
- `pc/.venv` no longer present in any commit

### Step 3 — Update `.gitignore`

To prevent this from happening again, virtual environment directories were added to `.gitignore`:

```gitignore
# Python virtual environments
.venv/
pc/.venv/
venv/
__pycache__/
*.pyc
```

### Step 4 — Commit and Force Push

The updated `.gitignore` was committed, the remote was re-added, and all branches were force-pushed:

```bash
git add .gitignore
git commit -m "fix: add .venv and __pycache__ to .gitignore"

git remote add origin https://github.com/00Juan/PCB-Tester-TFG-firmware.git
git push origin --force --all
```

All 10 existing branches were successfully updated on GitHub.

---

## Lessons Learned

| ❌ What went wrong | ✅ How to avoid it |
|---|---|
| `pc/.venv` was not in `.gitignore` | Always add `.venv/` to `.gitignore` before the first commit |
| Binary/generated files were tracked | Never commit auto-generated directories (`node_modules/`, `.venv/`, `build/`, etc.) |
| Large binary was deep in git history | Removing a committed large file requires history rewriting, not just a new commit |
